## 3. Audit design (fail-closed)

* **Kernel level** — `ReleaseAudit/Run.lean` imports both library roots and runs
  `#fail_closed_audit`: for **every** constant whose module root is one of `PrimitiveTree`,
  `TreeNumbers`, `TreeFoundation`, `DimensionFoundation`, `TreeFoundations`, `TreeAnalysis`,
  `BoundaryTopology` (plus constants of the invoking file), it computes `Lean.collectAxioms` and
  raises an **error** (`throwError`) if any axiom other than `propext`, `Quot.sound` occurs, if the
  constant is an `axiom`, `opaque` (how `partial` compiles), `unsafe` or `@[implemented_by]`, if it
  mentions a `Classical` constant, or — for handwritten constants — a built-in number constant
  (`Nat`, `Int`, `Rat`, `Fin`, `UInt*`, `USize`, `BitVec`, `Real`, `PNat`, `Float`, `OfNat`,
  `OfScientific`). Exemptions from the number check only: constants generated for inductive types
  (Lean's auxiliary-recursor/no-confusion predicates, or last name component in a fixed list:
  `ctorIdx`, `toCtorIdx`, `noConfusionType`, `noConfusion`, `sizeOf_spec`, `injEq`, `inj`,
  `below`, `brecOn`, `binductionOn`, `ibelow`, `casesOn`, `recOn`, `rec`, `ctorElim`,
  `ctorElimType`, `noConfusion_of_Nat`, `_sizeOf*`, `instSizeOf*`) and syntax constants (type
  `ParserDescr`, `TrailingParserDescr`, `Macro`, `Unexpander`). Abstracted proofs `_proof_n` and
  matchers `match_n` are **not** exempt. It also fails if fewer than 60 project modules are loaded.
  `#require_decls` fails if any of 47 central declarations is missing (43 before the Q14 repair).
* **Source level** — `scripts/source_check.py` strips comments and strings from all 62 (61 before the Q14 repair) mathematical
  source files and fails on forbidden identifiers/tactics (`Nat`, `Int`, `Rat`, `Fin`, `Real`, …,
  `List.length`, `replicate`, `Classical`, `classical`, `noncomputable`, `sorry`, `admit`, `axiom`,
  `unsafe`, `partial`, `native_decide`, `implemented_by`, `opaque`, `simp`, `simpa`, `omega`,
  `norm_num`, `ring`, `linarith`, `aesop`, `grind`, …), on any decimal literal, on any non-project
  import, and on any file not reachable from the two roots. (`decide` is not listed: the project
  uses the term `Decidable.decide` on its own decision procedures, e.g. `gapTest`.)
* **Boundary of infrastructure types.** The audit metaprograms use Lean's `Nat`, `String`,
  `Array`, `IO` for bookkeeping. They live only in `ReleaseAudit/` and `scripts/`, declare no
  mathematical constants, are never imported by a mathematical module (enforced by the source
  check's import rule) and are outside the audited module roots.

## 5. Limitations

* `leanchecker` is the lean4checker bundled with the pinned toolchain (invoked through the elan
  proxy `leanchecker`); it re-checks declarations with the same kernel, so it detects environment
  manipulation, not kernel bugs. No independent external checker (e.g. lean4lean) was available.
* `--fresh` was run on the two library roots (which transitively import every mathematical
  module); `ReleaseAudit` was replayed in the non-fresh mode only (its `--fresh` replay would
  re-check all of `Lean`, which it imports).
* The source check is a lexical screen (after comment/string removal); the semantic guarantee is
  the kernel-level audit.
* The generated-constant exemption relies on Lean's naming of auxiliary constants; it is listed
  exactly above and in `ReleaseAudit/Command.lean`, and the exempt constants are still subject to
  the axiom, classical and declaration-kind checks.
* Redundant helpers recorded, not consolidated: `pickD` (`BoundaryTopology/Cylinders.lean`) and
  `ifD` (`TreeAnalysis/SupremumScope.lean`) are identical; `absD x d = pickD d x (-x)`
  (`TreeAnalysis/OrderedField.lean`); `boolOf` (`TreeNumbers/PathRationalField.lean`) is distinct.
* Historical files (`REPORT*.md`, `FINAL_PROPERTY_MATRIX.md`, `FINAL_OPEN_PROBLEMS.md`,
  `FINAL_FOUNDATIONS_REPORT.md`, `Audit/`) are kept unchanged as records of earlier tasks; where
  they differ, the Task 05 documents take precedence.
